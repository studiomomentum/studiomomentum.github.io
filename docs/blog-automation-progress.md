# 블로그 자동화 v1 구현 현황

## 최신 상태 — 2단계 운영 배포

- 블로그 가독성: 네이버·티스토리 각 2개 글의 문단 구성을 참고해 생성 지침을 갱신했다. 플랫폼별 고정 글자 수 개행 대신 의미 단위 문단·소제목을 사용한다. 현재 두 블로그 초안은 문구를 바꾸지 않고 문단 여백만 조정해 v3로 보존 저장했다. 참고 URL과 관찰 한계는 실행기 README에 기록했다.

- 쓰레드 전용 말투 갱신: 친구에게 말하는 자연스러운 반말, 한 가지 생각·실천, 짧은 문장과 줄바꿈. 회사 소개·정형 홍보·마지막 URL 제외. 블로그 서비스 링크 규칙은 유지한다.
- 사용자가 동의한 대화체 예시를 쓰레드 초안 v3로 저장하고 v1/v2를 보존했다. 향후 생성 프롬프트와 링크 검증기를 수정하고 실행기를 재시작했다. 링크 없는 쓰레드 허용·링크 있는 쓰레드 거부·블로그 링크 필수 테스트 통과.

- 2026-09-29 구성 지침 갱신: 같은 핵심 주제·근거를 공유하되 서로 다른 독자 질문과 판단 상황을 다룬다. 매체별 형식 고정 및 단순 문장 치환은 하지 않는다.

## 1단계 조사 결과

로컬 실제 코드를 확인했다. 운영 로그인·서버 배포 상태를 이번 조사에서 실증한 것은 아니다.

| 대상 | 확인한 구조 | 구현 시 적용 |
|---|---|---|
| 관리 화면 | `admin.html`, `assets/admin-workspace.js`의 `setMainTab`, `updateFilterBar`, `renderTable` | 같은 주소에 콘텐츠 전용 화면 추가. 기존 타깃·발굴·유입 렌더링과 15초 갱신이 편집 내용을 지우지 않도록 분리 |
| 인증 | `assets/admin-auth.js`의 `MomentumAdmin.call`, `server/apps-script/AdminRelay.gs`의 서버 세션 검사 | 콘텐츠 읽기·쓰기 모두 기존 서버 인증 이후 처리. 화면 숨김만으로 보호하지 않음 |
| 서버 경계 | `Code.gs`가 `momentum_admin`만 중계, 기존 GET은 이벤트 배열 | 초안·사업 내부 설정을 공개 정적 JSON이나 telemetry GET에 포함하지 않음 |
| 현재 기능 | 서버 action에 콘텐츠 저장·생성·발행이 없음 | 기존 기능이 구현된 것으로 표시하지 않음 |
| 유입 | `momentum-runtime.js`가 `visit_id`, `arrival_source/host`, `utm_source/medium`, `applied_pricing` 기록 | 기존 방문·상담 클릭 연결 재사용 |
| 글 식별 | 공통 meta에 `utm_content`와 콘텐츠 ID 없음 | 4단계에서 최소 필드 추가와 방문·상담 전달 검증 필요 |

상위 데이터 흐름 문서에는 구 인증과 v4 배포 설명이 남아 있다. 현재 로컬 인증 판단은 README와 실제 서버 코드를 우선했다. 이번 작업은 해당 상위 문서의 운영 상태를 갱신하지 않았다.

## 플랫폼 연결 조사

- 네이버: [공식 블로그 API 종료 공지](https://developers.naver.com/notice/article/7527)의 제목과 주소를 재확인했다. 이번 웹 도구에서 본문은 추출되지 않았다. 공식 대체 글쓰기 API는 이번 조사에서 확보하지 못했다. 검색 API와 카페 글쓰기 API를 블로그 발행으로 대체하지 않는다.
- 티스토리: [공식 종료 공지](https://notice.tistory.com/2664)와 [공식 API 저장소](https://github.com/tistory/document-tistory-apis)가 Open API 종료를 안내한다. 과거 글쓰기 endpoint로 구현하지 않는다.
- 쓰레드: [Meta 공식 API 컬렉션](https://www.postman.com/meta/threads/documentation/dht3nzz/threads-api)에 글 생성·발행 경로가 있다. 계정 연결 및 `threads_basic`, `threads_content_publish` 권한이 필요하다. 실제 사용자 계정·앱·토큰·게시 결과는 미확인이다.

네이버 신규 ID 가용성, 티스토리 주소, 기존 쓰레드 계정은 미확인. 기존 네이버 블로그에는 접근·수정하지 않았다.

## 다음 구현 조건과 제안

사용자가 PC 브라우저 연동 검증과 기존 AI 구독·로컬 환경 확인을 선택했다. 이어서 계정 개설·블로그 세팅은 보이는 Chrome, 실제 동작은 헤드리스 Chrome을 사용하도록 확정했다. 네이버는 기존 계정을 사용한다는 후속 결정으로 변경됐다. 실제 운영할 블로그 주소는 아직 확인하지 않았다. 다른 매체의 계정 준비 상태는 미확인이다.

1. 네이버·티스토리: 로그인된 PC 브라우저 연결 가능성을 검증하거나, 연결 결정까지 제작·검수만 먼저 구현. 브라우저 방식은 PC 실행·로그인 유지·편집기 변화의 영향을 받으며 실제 가능 여부는 검증 전이다. 수동 복사를 직접 발행 완료로 계산하지 않는다.
2. 글 작성: 기존 구독/로컬 실행 환경을 확인할지, 유료 API를 사용할지 결정. 이후 실행 가능성과 비용을 확인하고 저장소·작업 실행 계약을 확정한다.
3. 주제 보충: 초기 5개, 주 1회 보충을 제안하되 아직 확정·예약하지 않았다. 검색 출처·관측일·검색량 미확인을 구분하고 과거 100개 초안을 확정 후보로 가져오지 않는다.
4. 저장: 기존 인증을 거치는 비공개 저장을 우선 검토. 사업 설정, 주제/근거, 매체별 문서 버전, 검수한 버전, 발행 시도/결과를 분리한다. 저장 방식은 실행 환경 확인 후 확정한다.

## 구현·검증 계약

- 주제 선택 전 자동 생성·발행하지 않는다. 네이버·티스토리는 블로그 영역, 쓰레드는 별도 영역.
- 편집/재생성은 새 버전을 저장하고 검수를 해제한다. 재생성은 사용자의 편집본을 덮어쓰지 않는다.
- 서버에서 현재 버전의 검수 여부를 확인한 뒤 발행. 전체 발행은 세 매체 검수 완료를 확인하고 이미 성공한 매체를 제외한다.
- 발행 응답 유실은 확인 필요로 보존하며 자동 재발행하지 않는다. 성공 플랫폼과 발행 버전·URL은 보존한다.
- 실제 초안 생성, 재접속 후 저장 복원, 버전 충돌, 검수 해제, 중복 발행 방지, 부분 실패를 검증한다.
- 데스크톱/모바일 편집 화면과 기존 타깃·발굴·유입 화면 회귀를 검증한다.
- 플랫폼별 실제 게시물 URL·본문 확인 전에는 연동 완료로 표시하지 않는다.
- 인바운드 링크에는 `vip`, 영업 `ref`, 관리자 preview를 넣지 않는다. 추적 추가 시 기존 VIP 재방문 정책을 보존한다.

## 현재 완료 범위

기획서·현행 코드와 연결 제약 조사 및 [Chrome 실행기](../automation/blog/README.md)를 구현했다. Playwright 1.63.0을 lockfile로 고정했다.

- `setup`: 계정 개설·로그인·블로그 설정용 보이는 Chrome.
- `probe`: 같은 전용 프로필을 사용하는 헤드리스 Chrome. 개인 Chrome과 분리.
- 실제 Chrome 테스트 2건 통과: 보이는 모드에서 헤드리스로 전환 후 쿠키·localStorage 유지, 로그인·추가 인증 상태 판별, 허용하지 않은 매체 거부.
- doctor: 실제 헤드리스 렌더링 성공, Codex CLI ChatGPT 로그인 확인. 글 생성 호출은 미실행.
- 네이버 홈페이지 헤드리스 접속 HTTP 200, `ACCOUNT_NOT_VERIFIED`. 로그인·블로그 소유권·편집·게시 성공을 의미하지 않는다.

어드민 UI·글 생성·초안 저장·발행 어댑터·자동 상주 실행은 미구현. 계정 개설 완료 및 발행 검증은 사용자 가입·설정 이후 진행한다. 공개 배포·푸시는 하지 않았다.

### 네이버 기존 계정 사용

사용자 후속 지시에 따라 네이버 setup 진입점을 신규 가입에서 기존 계정 로그인으로 변경했다. 기존 블로그 보존 원칙은 유지하며, 로그인만으로 특정 블로그를 발행 대상으로 확정하지 않는다.

### 기존 계정의 새 블로그 개설 확인

사용자 로그인 이후 보이는 전용 Chrome에서 블로그 홈의 실제 표시 항목을 확인했다. `블로그 아이디 만들기`는 표시되지 않았고, `내 블로그` 진입은 `https://blog.naver.com/jungkkuckma`로 이동했다. 기존 글·프로필·설정은 변경하지 않았다.

[네이버 공식 개설 안내](https://help.naver.com/service/5593/contents/15183?lang=ko&osType=COMMONOS)에 따르면 네이버 아이디당 블로그는 1개다. 현재 계정으로 기존 블로그를 보존하면서 두 번째 블로그를 새로 개설할 수 없다. 블로그가 없는 다른 기존 계정 사용 또는 별도 계정 마련 결정이 필요하다. 기존 블로그 초기화·주소 변경은 수행하지 않는다.

### 기존 블로그 초기화 요청 진행

사용자가 기존 블로그 초기화 및 백업 생략을 명시적으로 승인했다. 기존 비공개 글 21개를 확인했으나 백업 생성은 하지 않았다. 보이는 Chrome의 초기화 화면에서 `24시간 이내`를 선택하고 `블로그 초기화 신청`을 눌렀다. 화면상 예정일은 2026-09-30 새벽이며, 현재 네이버 재로그인/본인 인증 창에서 사용자 입력 대기 중이다. 신청 접수 완료 및 실제 삭제는 아직 확인되지 않았다. 화면에는 초기화 후에도 블로그 주소를 재설정할 수 없다고 안내되어 있다.

### 티스토리 새 주소 개설 준비

사용자가 로그인한 자동화용 Chrome 세션에서 확인했다. 기존 `cockedpistol.tistory.com` 외에 추가 운영 가능 4개, 개설 가능 횟수 9회가 표시됐다. 기존 블로그 삭제 없이 새 주소 개설이 가능하다. 새 블로그 양식에 이름 `솟 모멘텀 | 유튜브 영상제작`, 주소 `sotmomentum`, 닉네임 `솟 모멘텀`을 입력했고 `사용할 수 있는 주소입니다` 응답을 확인했다. reCAPTCHA 사용자 확인 대기 상태로 개설 버튼은 비활성화되어 있으며 아직 개설하지 않았다. 기존 블로그는 변경하지 않았다.

### 티스토리 개설 완료 및 설정 팝업 수정

자동화에 dialog 처리기가 없어 Chrome 확인창이 자동 dismiss되는 원인을 확인했다. 설정 모드의 기존·신규 탭에 팝업 유지 처리를 추가했다. 운영 모드의 자동 승인 기능은 추가하지 않았다. 승인된 sotmomentum.tistory.com 개설 확인을 처리하고 `블로그 개설 완료`, `솟 모멘텀 | 유튜브 영상제작` 문구를 실제 화면에서 확인했다. 기존 cockedpistol 블로그는 변경하지 않았다. 글 발행 자동화는 아직 미검증이다.
