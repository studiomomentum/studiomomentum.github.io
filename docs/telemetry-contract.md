# 방문 추적 데이터 계약 (v2, 2026-10-19)

- `event_id`: 이벤트당 하나. 재전송·ntfy·Drive 저장에서 동일하게 유지한다.
- `meta.visitor_id`: 해당 브라우저 저장소의 식별자. 사람 수가 아니다. 저장소 삭제·차단·다른 브라우저는 구분할 수 없다.
- `meta.session_id`: 탭의 방문 세션. 30분간 이벤트가 없으면 다음 이벤트부터 새 세션이다. 새 탭은 별도 세션이다.
- `meta.visit_id`: 페이지 인스턴스 식별자. 다른 페이지로 이동하면 바뀐다. 세션 만료 시에도 바뀐다.
- `ref`: 아웃바운드에서는 고객 추적키. 자연유입에서는 세션 진입 페이지의 추적키를 이어서 사용한다. 추적키를 방문자 수나 세션 수로 세지 않는다.
- `path`, `meta.arrival_*`: 현재 페이지와 그 페이지로 들어온 출처.
- `meta.entry_*`: 세션 최초 진입 출처·경로. 내부 이동으로 덮어쓰지 않는다. UTM은 캠페인 표기이며 검색·AI 인용의 증명이 아니다.
- `timestamp`: 밀리초, `time`: 같은 시각의 ISO 문자열. 관리 화면은 한국시간으로 표시한다.

## 지표

페이지 조회는 `visit`/`view`만 세며 같은 `visit_id`는 한 번만 센다. 스크롤·체류·버튼 클릭은 조회 수에 더하지 않는다. 세션과 브라우저 수는 v2 식별자가 있는 기록만 계산한다. 과거 기록에서 인원·세션을 추정하지 않는다.

체류는 `performance.now()` 기반으로 화면이 visible이고 브라우저 창에 포커스가 있는 시간만 누적한다. 10/30/60/90초 마일스톤과 15초 주기의 `engagement`, 숨김/이탈의 `leave`에 `active_duration`을 기록한다. 화면을 다시 열면 누적을 재개한다. 합계는 페이지별 최댓값을 더한다. 체크포인트를 합산하지 않는다. 화면이 보였다는 측정이며 실제 사람이 읽었다는 증거는 아니다. 마지막 체크포인트 없이 브라우저가 강제 종료되면 마지막 구간은 알 수 없다.

`kakao_click`/`pay_and_kakao_connect`는 상담 연결 클릭이다. 상담 완료·결제 완료·매출로 간주하지 않는다. ROI 평균은 유효한 실제 입력값만 계산하며 표본이 없으면 ‘기록 없음’이다.

## 전송과 저장 확인

전송 전 이벤트별 `sm_telemetry_pending_v2:<event_id>` 키로 localStorage에 보관한다. ntfy의 HTTP 성공과 Drive 저장을 구분한다. Google Apps Script의 opaque 응답이나 sendBeacon 성공은 저장 확인이 아니다. Drive의 기존 GET API에서 같은 `event_id`를 읽은 뒤에만 대기열에서 제거한다. 실패 시 원래 ID로 재전송하며 페이지 재방문·온라인 복귀에도 재시도한다. 여러 탭이 재전송하더라도 서버는 ID로 중복 제거한다.

저장소가 차단되거나 가득 차면 메모리 대기열로 동작하며 `MomentumCollector.status().storageError`로 진단한다. 이 경우 브라우저 종료 후 복구는 보장할 수 없다. 웹페이지가 닫혀 있는 동안에는 브라우저 재시도를 실행할 수 없다. ntfy 서버를 읽는 기존 우분투 보관 작업은 별도로 유지된다. 과거에 유실됐거나 측정하지 않은 데이터는 만들어 채우지 않는다.

검증: `node tests/tracking-v2.cjs`, Playwright 기반 `tests/tracking-v2-ui.cjs`, 기존 날짜·보관·유입·어드민 회귀 테스트.
